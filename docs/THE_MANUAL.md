# The Manual — working public product name

**Status:** working title / product-direction note. This does **not** rename the repository, API contracts, or Human Metadata Engine yet.

## Core idea

People routinely say some version of: *I wasn't given a manual when I got here*, or *kids don't come with a manual*.

**The Manual** is Inversion Labs' answer to that gap: an optional, inspectable personal reference built from the information a person chooses to provide and from clearly labeled calculation, symbolic, assessment, timing, and contextual systems.

A concise working line is:

> **The manual you were never issued — if you want one.**

The last clause matters. The product is not an authority assigning a destiny, diagnosis, identity, or correct way to live. It is a structured set of lenses whose inputs, conventions, provenance, uncertainty, and limitations remain visible to the person using it.

## Naming stack

- **The Manual** — working public product name: the thing a person opens and uses.
- **Human Metadata Atlas** — the visual exploration surface inside The Manual.
- **The Living Pattern** — the evidence-linked narrative/synthesis layer.
- **Human Capacity / Sumerian me Reflection** — an optional, user-tagged comparison from observed experience through a modern capacity crosswalk to a bounded historical corpus; never an ancient personality assignment.
- **Human Metadata Engine** — the deterministic, provenance-aware computational core.
- **signature-v3 / system-result-v2** — versioned machine contracts beneath the product.

This split lets the public identity become warmer and immediately understandable without throwing away the technical name, repository history, or stable contracts.

## Product principles implied by the name

1. **Optional, not prescriptive.** A manual is available if one desires it; it is not a rulebook imposed on the person.
2. **Inspectable.** A useful manual shows where a result came from, what inputs it used, and which convention produced it.
3. **Multiple lenses are not multiple proofs.** Systems sharing the same dependency remain correlated views, not independent confirmations.
4. **Known unknowns stay unknown.** Missing birth time, ambiguous civil time, proprietary assessment data, or unsupported cultural material is withheld or labeled rather than fabricated.
5. **Data and interpretation stay distinguishable.** Calculated coordinates, historical/textual references, user-supplied observations, modern analytical crosswalks, traditional symbolic interpretations, and synthesis are different epistemic classes.
6. **The person remains the authority on the person.** The Manual is a reference instrument, not a verdict.

## Rename boundary

Do not rename the repository, package/module names, API identifiers, database contracts, or deployment identifiers merely because this working title exists. A hard rename should be a separate migration after the public name, subtitle, visual identity, search/domain implications, and compatibility redirects are deliberately approved.
